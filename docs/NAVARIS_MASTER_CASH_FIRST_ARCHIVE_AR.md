## 9. Source of truth and controls

1. This file is the consolidated operating index; supporting files remain evidence and must not be silently overwritten.
2. Every opportunity needs a stable ID, buyer/contact path, official source, scope, need-by date, budget/procurement path, owner, next action and due date.
3. Every claim needs exact wording, source, evidence file/hash, date checked, scope, expiry/review date and status: VERIFIED, DOCUMENTED_NOT_INDEPENDENTLY_VERIFIED, TARGET, UNVERIFIED or EXPIRED.
4. Cash lifecycle: DRAFT → INVOICED → PAYMENT_PENDING → RECEIPT_EVIDENCE_UPLOADED → RECONCILIATION_PENDING → RECEIVED_VERIFIED or REJECTED. Only RECEIVED_VERIFIED counts.
5. Do not store confidential client/bank information in the unencrypted Electron SQLite placeholder. Never commit API keys or credentials.
6. External messages, bids, binding prices, contracts, purchases, bookings or partnership commitments require founder approval unless a specific recurring report automation is explicitly authorised.
7. Missing data stays UNKNOWN; unknown is neither zero nor permission to infer.
