# NAVARIS Cross-Platform App — Scaffold

This is an isolated application workspace. It does **not** replace the existing Python engines, skills, automation workflows, or root `index.html`.

## Architecture decision
- **UI:** React + TypeScript + Vite.
- **Shared logic:** TypeScript modules under `src/core`, with deterministic unit tests.
- **Web:** static Vite build (`dist/`), deployable to any static host.
- **Android/iOS:** Capacitor wraps the same web build. Android APK/AAB requires Android Studio/SDK; iOS requires macOS and Xcode.
- **Windows:** Tauri 2 wraps the same web UI in a small native shell. Windows build requires Rust and Microsoft C++ Build Tools; WebView2 is the rendering runtime. Tauri installers can be configured to bootstrap WebView2. A truly dependency-free single EXE cannot be promised for all Windows machines.
- **Existing Python engines:** remain a separate local/service boundary until explicit API contracts, authentication, and deployment model are approved. Never embed API keys or credentials in client code.

## Requirements
- Node.js LTS and npm.
- Windows build: Rust stable, Microsoft C++ Build Tools, WebView2.
- Android: Android Studio, Android SDK, JDK version required by the current Capacitor/Gradle toolchain.
- iOS: macOS + Xcode.
- Git.

## Commands (from repository root)
```bash
cd cross-platform
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

### Android
```bash
npm run cap:sync
npm run cap:android
```
Then use Android Studio to select a device and build a debug APK, or run:
```bash
cd android
./gradlew assembleDebug
```
Windows PowerShell: `.\gradlew.bat assembleDebug`.

### Windows desktop (Tauri)
First install Rust and Microsoft C++ Build Tools, then:
```bash
npm run tauri:dev
npm run tauri:build
```
Installer/bundle output is produced under `src-tauri/target/release/bundle/`. Confirm WebView2 installation strategy and sign release binaries before production distribution.

### Web
```bash
npm run build
npm run preview
```
Publish the contents of `dist/` to a static host. Configure the hosting base path if deploying beneath a repository subpath.

## Important constraints / integration plan
1. This scaffold only proves a shared UI/core pattern; it is not yet a production NAVARIS application.
2. Add screens incrementally: Opportunity Register, Supplier/Carrier Qualification, Deal Gates, Landed Cost, Net Commission, Financial Analysis, and Audit Log.
3. Persist data only after choosing the data classification, backup, encryption, and sync/conflict strategy. Browser local storage is not a secure multi-user database.
4. Background execution is platform-specific. Web tabs can be suspended; use a server-side worker or OS scheduler for reliable jobs. Mobile background tasks require native platform APIs and user permissions.
5. All external communications must remain draft-only until the user approves the exact recipient and final message. Never place mail/WhatsApp secrets in the client.
6. Require source links, timestamp, author, evidence state, and audit trail for each opportunity. CASH COLLECTED must remain zero until payment evidence is verified.
7. Run tests on Windows and Android emulators/real devices before declaring production-ready. CI is not a substitute for device validation.

## Scaffold status
This is a starting point, not a signed-off production release. The current repository is a mixed Python/HTML workspace; its existing package/dependency files and automation workflows should be preserved until their responsibilities are separated deliberately.
